# Job Requests

Job Requests capture hiring demand and move it through review, routing, sourcing, and final closure.

## Creating A Request

Presales or another approved internal user can create a job request when a hiring need is identified.

Typical fields:

- Job title
- Department
- Hiring manager
- Priority
- Required skills
- Experience expectations
- Headcount
- Business justification
- Target start date

## Request Review

After creation, a request may be routed to PMO for bench review or operational validation.

PMO review can include:

- Demand clarification
- Bench employee matching
- Recommendation notes
- Route to recruiter
- Return for changes

## Ownership

Workflow ownership should be explicit.

Examples:

- Presales owns request creation.
- PMO owns routed review tasks.
- Recruiter owns sourcing and job publishing once assigned.
- Hiring Manager owns final review and closure decisions.
- Tenant Admin can override when configuration or ownership is blocked.

## Request Detail

The job request detail page should show:

- Request summary
- Current status
- Assignment owner
- Workflow history
- Bench matching context
- Candidate and job post links when available
- Close or action controls based on permission

## Closing A Request

Closing a request should require a business reason. Closed requests should remain available for reporting and audit, but should no longer accept new candidate work unless reopened through a deliberate future workflow.
